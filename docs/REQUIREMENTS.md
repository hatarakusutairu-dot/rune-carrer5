# 要件定義書

最終更新：2026-04-28

## 1. プロジェクト概要

### 1.1 プロジェクト名
rune-carrer5（高校eスポーツコース 60分授業進行アプリ）

### 1.2 背景
高校eスポーツコースの初回授業で、生徒に対し以下を伝えたい。

- ゲームで育つ力は社会にも活きる
- AI面接やアバター面接など、新しい採用形態が登場している
- ゲーム的体験への慣れは強みになり得る
- この高校で過ごす1年には意味がある

ただし、初回授業ではKahootが正常動作しない可能性があり、また最大300名規模で
同時参加することがある。そのため、Kahootと外部サーバーに依存せず、アプリ単体
で60分授業を成立させる設計が求められる。

### 1.3 目的（最終ゴール）
授業後に生徒が以下を感じられること。

- ゲームは無駄ではない
- ゲームで育つ力は社会にもつながる
- この高校で過ごす時間には意味がある
- この1年、自分の強みを育ててみよう

## 2. 利用者と利用環境

### 2.1 利用者

| 役割 | 想定人数 | 利用画面 |
|---|---|---|
| 講師 | 1〜数名 | 講師モード（スクリーン投影） |
| 生徒 | 最大300名/同時 | 生徒モード（個人スマホ/PC） |

### 2.2 利用環境
- 教室・体育館等
- 講師：PCをスクリーンに投影
- 生徒：個人スマホまたはPCのブラウザ
- 通信：学校Wi-Fi（不安定の可能性あり）

---

## 3. 最重要要件（MUST）

| ID | 要件 |
|---|---|
| R-01 | Kahootなしでも60分授業が成立すること |
| R-02 | 300名規模の同時アクセスでも軽快に動作すること |
| R-03 | 生徒回答処理が各端末内で完結すること（サーバー処理を発生させない） |
| R-04 | 個人情報（氏名・学籍番号等）を一切保存しないこと |
| R-05 | ログイン不要で参加できること |
| R-06 | 診断結果は断定せず、前向きな自己理解として表示すること |
| R-07 | 通信不安定時にも進行できるフォールバックモードがあること |
| R-08 | スマホで軽快に動作すること |

## 5. 非機能要件

### 5.1 パフォーマンス

| ID | 要件 |
|---|---|
| N-P-01 | 300名同時アクセス時も初回ロードが軽快であること |
| N-P-02 | 静的アセット（画像・動画）は最小化すること |
| N-P-03 | 初回ロード後はオフラインでも進行できること |
| N-P-04 | スマホ実機で60fps相当の操作感を確保すること |

### 5.2 可用性

| ID | 要件 |
|---|---|
| N-A-01 | サーバーダウンの影響を受けない構成（静的配信） |
| N-A-02 | Kahoot不調時にも授業が止まらない |
| N-A-03 | 通信断時も読み込み済みなら継続利用可能 |

### 5.3 セキュリティ・プライバシー

| ID | 要件 |
|---|---|
| N-S-01 | 個人名・学籍番号等の個人識別情報を取得しない |
| N-S-02 | 外部DBへの送信を行わない |
| N-S-03 | localStorageの内容は授業後にリセット可能 |
| N-S-04 | Cookie・トラッキングを行わない |

### 5.4 ユーザビリティ

| ID | 要件 |
|---|---|
| N-U-01 | スマホ画面で読みやすい文字サイズ・コントラスト |
| N-U-02 | 1画面1アクションを基本とする |
| N-U-03 | ボタン操作のみで進行可能（テキスト入力は最小限） |
| N-U-04 | 結果画面はスクショに最適化 |

### 5.5 表現の倫理

| ID | 要件 |
|---|---|
| N-E-01 | 「あなたは〇〇な人」と断定しない |
| N-E-02 | 「今日の選択では〇〇の傾向が見えました」と表現する |
| N-E-03 | 評価・優劣・分類を示唆しない |
| N-E-04 | 全ての生徒が前向きに受け取れるメッセージ設計 |

## 6. 授業フロー（Stage定義）

詳細は [STAGES.md](STAGES.md) を参照。

| Stage | 時間 | タイトル | 主目的 |
|---|---|---|---|
| 0 | 0〜5分 | Start / 今日のミッション | 安心感の醸成 |
| 1 | 5〜20分 | Mini Game / 採用系ミニアプリ体験 | 自分の傾向に触れる |
| 2 | 20〜27分 | Result / 強みの芽診断 | 自己理解の入口 |
| 3 | 27〜34分 | Share / ペア・グループ共有 | 他者理解 |
| 4 | 34〜42分 | Reveal / 今の採用とつなげる | 社会接続の認識 |
| 5 | 42〜52分 | Skill Link / 社会で活きる力 | 因果の理解 |
| 6 | 52〜60分 | My Quest / この1年で育てたい力 | 自分の言葉で着地 |

- 氏名
- 学籍番号
- メールアドレス
- IPアドレス

## 8. Kahootの位置づけ

Kahootは授業の補助ツール。**必須ではない**。

| 状況 | 動作 |
|---|---|
| Kahoot動作する場合 | クラス全体傾向の可視化に利用 |
| Kahoot動作しない場合 | 講師画面の代替問いで進行 |
| アプリも入れない生徒 | 紙・メモ・挙手で参加可能 |

## 9. 技術選定（推奨）

詳細は [ARCHITECTURE.md](ARCHITECTURE.md) を参照。

- フロントエンド：React + Vite + TypeScript
- スタイル：Tailwind CSS（軽量）
- 配信：GitHub Pages / Netlify / Vercel
- データ：localStorage / sessionStorage
- バックエンド：**なし**（静的Webアプリ）
- 状態管理：React Context（軽量）

## 10. 受け入れ基準

| ID | 基準 |
|---|---|
| AC-01 | Kahootを完全停止しても60分授業を進行できる |
| AC-02 | 模擬300セッション同時アクセスで初回ロード3秒以内 |
| AC-03 | 個人情報入力フォームが画面上に存在しない |

| AC-05 | 全Stageが断定的表現を含まない |

| AC-07 | 講師画面のみで全Stageを完了できる（生徒画面なしでも進行可） |
