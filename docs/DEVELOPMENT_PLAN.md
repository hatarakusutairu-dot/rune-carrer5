## 5. 想定リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 学校Wi-Fiが極端に弱い | 生徒がアプリに入れない | フォールバックモードで講師画面のみ進行可能に |
| 300名同時アクセスでロード遅延 | 授業開始が遅れる | 静的配信＋CDN、バンドル軽量化 |
| Kahootが当日動かない | 全体共有ができない | 代替問いを講師画面に常備 |
| 個人情報を誤って収集 | プライバシー違反 | 入力フォーム自体を作らない（レビュー必須） |
| 診断結果が断定的に読める | 生徒を傷つける | 文言レビュー専用チェックリスト |
| スマホ実機で表示崩れ | 生徒UXが悪い | 主要機種で実機確認 |

## 6. 負荷検証計画

### 6.1 模擬300セッション
- ブラウザ自動化（Playwright等）で300並列アクセス
- 初回ロード時間・応答時間を計測
- localStorage書き込み速度を確認

### 6.2 検証指標

| 指標 | 目標 |
|---|---|
| 初回ロード時間（4G） | < 3秒 |
| 初回ロード時間（学校Wi-Fi想定） | < 5秒 |
| 1ボタン押下のレスポンス | < 100ms |
| 全Stage完走率 | 100% |

## 7. レビュー観点

### 7.1 機能レビュー
- 全Stageが順番に進む
- 戻るボタンで前Stageに戻れる
- リセットで初期化される

### 7.2 表現レビュー
- 断定的表現がない
- 否定的表現がない
- 全タイプが肯定的に書かれている
- 将来とのつながりが示されている

### 7.3 セキュリティ・プライバシーレビュー
- 個人情報入力欄がない
- 外部送信が発生していない
- localStorage以外への書き込みがない

### 7.4 パフォーマンスレビュー
- バンドルサイズが目標内
- 画像が最適化されている
- 不要な再レンダリングがない
