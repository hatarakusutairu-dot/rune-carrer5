## 1. 開発方針

- **MVPファースト**：初回授業で確実に動くものを最優先
- **静的Webアプリ + Cloudflare Workers**（DBなし、揮発のみ）
- **段階リリース**：Pass単位でcommit/push、ユーザー確認後に次へ

## 3. Pass分割（Phase 2の進め方）

ユーザー確認を挟みながら進める。

| Pass | 内容 | 確認ポイント |
|---|---|---|
| **Pass 1** | 設計書更新 + Worker scaffold + サーバー実装 | アーキ承認 |
| **Pass 2** | クライアント同期層 + ルーム作成・入室 + クラス選択 + リアクション | 入室フロー承認 |
| **Pass 3** | 採用ゲーム7種実装 | ゲーム挙動承認 |
| **Pass 4** | 集計・レーダー・分析カード・キャラ競争 | 集計UX承認 |
| **Pass 5** | 演出（入室の森、カウントダウン、待機アニメ） | 没入感承認 |
| **Pass 6** | AI画像差し込み + 文言調整 + フォールバック | 文言承認 |
| **Pass 7** | デプロイ + 実機検証 + 負荷テスト | 本番投入 |

各Passの境界で commit + push し、ユーザー確認後に次へ。

## 5. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| Workers有料プラン未加入 | デプロイ不可 | ユーザー作業、代替の無料案も用意 |
| 300人接続でDOボトルネック | 同期遅延 | Hibernation使用、メッセージ最小化 |
| WebSocket切断頻発 | 進行不能 | 自動再接続 + ローカルフォールバック |
| AI画像未到着 | 演出半端 | テキスト/絵文字フォールバック |
| Kahootも同期も失敗 | 授業崩壊 | 講師画面のみで進行可能（緊急モード） |

## 6. レビュー観点

### 機能
- 全Stageが順番に進む
- 講師がペース管理できる、生徒は先回り不可
- 途中参加が可能
- リセットで初期化

### 表現
- 断定的表現がない
- 否定的表現がない
- 全タイプ・全クラスが肯定的

### セキュリティ
- 個人情報入力欄なし
- 永続DB書き込みなし
- localStorage は授業後リセット可

### パフォーマンス
- 初回バンドル < 250KB gzip
- WebSocket遅延 < 1秒
- スマホで操作レスポンス < 100ms
